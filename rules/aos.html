Designed by Jonathan Weeks

Automaton of Shale (AoS)

Build it from what you can make work, then find out what you built.

You are the Technician assembling Nobulous’ automaton from whatever you can get working. Each Program is a row of elements funded in full before a single die is rolled — and Nobulous names the dice you may not use first. Run one cleanly and it becomes a part; three finished Assemblies become the machine, and only then do you learn what it was built to do.

Components

  • 6 Experimental Technician cards
  • 32 Program cards (double‑sided Stable / Overheated) in four decks of 8: Routine, Specialized, Unstable, Volatile
  • 8 Assembly cards — double‑sided, recipe on the front and the Advanced Program it becomes on the back
  • 6 Limitation cards
  • 5 Element allocation mats
  • From 20 Strong: the 17 unit dice — 4 Purple, 4 Blue, 4 Green, 4 Yellow, 1 Red
  • From 20 Strong: the 3 stat dice — HP, STR, REC — and the Chip

  6. All 17 dice start available.

Object of the game

You have three rounds to build three Assemblies. An Assembly is a recipe: a row of Build slots, each wanting one Program you have run cleanly. Build the third and the game goes straight to the finale, where those three Assemblies turn over and become the three stages of a single Advanced Program. Come out of the finale with at most one failed element and at least 1 Health and you have won.

If your Health reaches 0 at any point you lose — and so does reaching the end of round three without three Assemblies built. Health can be raised by Program Rewards but never above 6, and a Reward needs a Program finished with no failed elements, so the only way to heal is the same work that builds the machine.

Rounds

A round is one pass through every Program still available to run: shuffle them, then run each once, in the order it comes up. Programs leave the deck when they are set aside, when a Program Reward removes them, and — the new one — when they are installed in a Build slot, so later rounds are shorter. Finish your third Assembly and you go to the finale at once, whatever is still in the deck. Otherwise the third round is the last.

Running a Program

This order matters more than anything else in the game.

  1. Reveal the Program. It shows a row of elements, each with a Target, and one element ringed as the overheat marker.
  2. Reveal the Limitation. It withholds dice from your available pool or imposes a constraint. Withheld dice cannot be used in this Program at all — not even for a required color.
  3. Commit required‑color dice. Every colored dot beside an element requires one available die of that color to be placed on that element now. These dice are locked there.
  4. Finish the allocation. Distribute the rest of your available dice across the elements. Every element must receive at least one die. If you hold fewer available dice than the Program has elements, place what you have and the elements left bare fail.
  5. Execute. Roll each element and resolve it. A hit is 1 success, a Crit is 2.
  6. Recover dice equal to your REC at the end of every Program, before the next one is revealed.
Required colors Red can never satisfy a required‑color dot. A required die counts normally toward its element’s Target — it just has to be that color, and it has to come from the dice the Limitation left you.
If you cannot supply a required color Do not execute the Program. Lose 1 Health. Return any withheld dice, discard the Limitation, and treat the Program as failed for Stable/Overheated progression, then move on. Running your colors dry — or letting a Shortage do it for you — has a real cost.

Routine, Unstable and Volatile Programs carry one required‑color dot and Specialized carry two, with one exception that asks for more: Carry a Moving Load requires all four colors. Read the card rather than the deck. The same required colors appear on both faces of a Program card — and those same dots are what decide which Build slots the Program can fill.

Limitations

Reveal exactly 1 Limitation per Program, right after the Program and before any required‑color dice are committed. Each withholds dice from your pool, as printed. Withheld dice return when the Program ends; discard the Limitation then.

Allocation floor and cap

An element may hold at most Target + 1 dice, unless a card raises that cap — the Engineer does, for up to 2 elements per Program — and never fewer than one.

The floor is there because an element you abandon is one you have decided to lose, and that decision should cost something. A failed element exhausts every die allocated to it, so the floor is exactly the price of the decision: one die, your worst, gone. Nothing else about failing changes.

Rolling and the exhaustion gradient

Each element gets one Strategy roll. Additional rolls up to your STR form a shared pool spent anywhere in the Program — at STR 2 that is one extra roll for the whole Program. An extra roll is a full reroll of that element’s dice: pick the element up, roll all of them again, and the new result replaces the old one, better or worse.

Dice come back unless you are punished Allocating dice is not spending them. When an element resolves, its dice return to your available pool — except for the ones the table below burns.

Anything not listed below costs nothing.

If an element uses an extra roll and lands exactly on Target, both apply: exhaust its dice first, then recover 2 — which may include dice you just exhausted.

Catastrophic Failure Failing exactly one element in a Program costs no Health. Failing two or more in the same Program is one Catastrophic Failure and costs 1 Health total.

When a Catastrophic Failure occurs, you may exhaust 2 misses on failed elements to negate the Health loss. Count only misses still showing after any rerolls, and only on elements that actually failed.

Those dice were exhausting anyway — a failed element exhausts everything allocated to it — so the negation costs you nothing beyond having the misses there to spend. That is the point of it: an element you have already given up on is worth loading rather than leaving bare, and the saving throw is a common out rather than a rare one.

Program Rewards

Every Program in the Routine, Specialized, Unstable and Volatile decks prints a Program Reward. Claim it when you complete that Program with no failed elements at all — one failure is enough to lose it, even though one failure costs no Health.

The reward is printed on the Program. Two of them — +1 REC and +1 STR — are permanent, and remove that Program from the deck when claimed. Assembly backs carry no reward.

Installing a Program

Finishing a Program does two things, and the second is how the game is won. Complete one without a Catastrophic Failure — that is, with at most one failed element — and you may install it in one open Build slot on one revealed Assembly.

Installing is not the Reward The two conditions are deliberately different. The Reward needs a clean run, no failed element at all. Installing needs only that the Program survived — one failure costs you the Reward and flips the card to Overheated, and that is already price enough. Charging the same failed element twice makes the three‑round deadline unreachable: the machine gets built out of work that went mostly right, which is the whole idea.
  • A Program fills one slot and counts as one color, chosen from its printed required‑color dots as it goes in. A Program with a Purple dot and a Yellow dot can take a Purple slot or a Yellow slot — not both, and the choice is made once.
  • Two Purple slots need two separate Programs. No card ever fills more than one slot.
  • An installed Program is held out of the deck while it stays there. Leave it physically in its slot, turned so the color it was installed as is the one on show.
  • Installing is optional. A Program with nowhere useful to put it still pays its Reward, if the run was clean.

An Assembly with a Program in every slot is built. A built Assembly is locked: it cannot be dismantled, and its Programs are gone for the rest of the game.

The two permanent Rewards can still go in a slot +1 REC and +1 STR normally remove their Program from the deck when claimed. Install it instead and it goes to the slot rather than the box: take the stat, mark the Reward claimed, and leave the card in the Assembly. Should it ever come back — see abandonment — it can be run and installed again, but the permanent Reward is not earned twice. Never install it and it leaves the deck exactly as printed.

Abandoning an Assembly

You may give up an unfinished Assembly whenever you like. Lose 1 Health if it holds at least one Program — an empty one costs nothing — then clear its slots. Every Program that was in it flips to Overheated and returns to the deck at the next round boundary, not at once.

A returned Program must survive a new run before it can be installed anywhere again, and may take either eligible color the second time. The Assembly stays in your offer and can be started over.

The delay is the real cost. Abandon during round three and the Programs come back after the deadline has passed, which is to say they do not come back at all.

Stable, Overheated, set aside

  • When a Stable Program fails, flip it to Overheated. The ringed element’s Target increases on that face.
  • If an Overheated Program fails again on a later appearance, set it aside.
  • A Program set aside is out of the game: it can never be installed, and the slot it was meant for needs another card.

The finale: one Program in three stages

The moment the third Assembly is built, turn all three over. Their backs are the three stages of a single Advanced Program. Randomize their order and keep the Targets hidden — number them 1, 2, 3 and shuffle the numbers if that is easier — then reveal and resolve one stage at a time.

You have read each Assembly’s Advanced colors line all game, so you know which colors the finale will ask of you. What you have never seen is how many elements a stage has, or a single Target.

  • Each stage counts as one Program for Limitation, Strategy and Recovery. Reveal 1 Limitation per stage.
  • Recover after the last construction run, and again between stages.
  • Every element carries a required color — which a Program element usually does not — and pre‑allocation works exactly as it has all game. If you cannot supply one, lose 1 Health as usual and every element in that stage counts as failed.
  • An Assembly back has one set of Targets. There is no Overheated side, and nothing carries from one stage to the next.
Winning The three stages are one Program, so count failed elements across all three together. At most one, and at least 1 Health left, and you have won AoS. The second failed element is a Catastrophic Failure on that one Program and loses the game outright.

Which retires the exhaust 2 misses save for the rest of the game. It was only ever buying off the Health cost of a Catastrophic Failure, and in the finale the second failure does not cost Health — it ends the game. Plan the colors instead: a stage you cannot supply fails every element it has, and that is two at once.

Giving up an element is a decision, not a free move Writing off an element you cannot fund is proper play, not an exploit. One failed element costs no Health, and its dice are often worth more concentrated on the elements you can finish — landing one exactly on its Target pays Optimal Implementation. Knowing when to do it is most of the skill in AoS.

What it is not is free. Every element must hold a die, and a failed element exhausts every die on it, so each element you give up costs you one. And a Program with any failed element pays no Program Reward.

That last clause is what closes the door on failing your way through the game. Giving up one element is a real option — the Program still installs. Giving up a second is not: that is a Catastrophic Failure, and a Program that suffers one pays no Reward and cannot be installed, so it costs a Health, builds nothing, and heals nothing while the three‑round deadline runs. The only way to heal is the same work that builds the machine. Write off two elements a Program and you reach round three with an empty frame and no Health to show for it.

Which is why the decision is sharper here than it reads. Giving up an element on a Program you were never going to install — one whose colors fit no open slot — costs you a die and nothing else. Giving up an element on the Program that was going to fill your last Purple slot costs you the Assembly.

Carrying AoS forward

Only relevant if you are playing the Nobulous Research Journal (NRJ) campaign, which is Tier III only.

AoS contributes its 6 Backdoor Routines, and nothing leaves the Program decks. A Routine you claimed is retained — at most 2, which is the claim limit a game — and the rest are candidates.

Tier III also adds a ninth Assembly, the Covert Sensor Array, printed in the campaign supplement. It replaces the standard Sensor Array for that setup and is always one of the 6 revealed; the other 5 come from the remaining 7. Build it, and run its stage — Erase the Audit Trail — with no failed element, and it is retained for the Imposter Scenario, where it answers a Cover‑Up Exhibit by reducing its Target by 2. It shares the cap of 2 AoS retentions with the Backdoor Routines; if more than two qualify, choose which two to keep. A Covert Sensor Array you did not earn is not in the pool at all.

A retained Routine answers Cover‑Up Exhibits in the finale, reducing a Target by 2; it does not matter whether you went on to spend it. Claiming one costs the next Program Reward you would have taken, which is a real price — and two of those Rewards are the permanent +1 REC and +1 STR.

Root Access is worth holding — and the advice flips at the finale Its use is to treat a failed element as successful. During the game that is usually a waste: the printed rule already lets you exhaust 2 misses on failed elements to negate the Health loss for nothing, so spending a Routine before trying the misses throws it away on a problem you had already solved. Try the misses first.

In the finale it is the only thing that works. The misses save buys off Health, and the second failed element there does not cost Health — it loses the game. Root Access turns that second failure back into a success, which is the difference between winning and not.
